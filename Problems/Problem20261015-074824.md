## 任务目标

修复 `www.patfang.xyz` 和 `PatTianFang.github.io` 访问时出现 GitHub Pages 404 的问题，并确认仓库当前发布状态。

## 思考过程

仓库是 GitHub 用户站点 `PatTianFang.github.io`，根目录存在 `index.html`，当前分支是 `master`。因此需要分别核对源站发布和自定义域名绑定。DNS 显示 `www.patfang.xyz` 的 CNAME 指向 `pattianfang.github.io`；Git 历史显示仓库此前声明的自定义域名为 `www.patfang.xyz`，但该文件在 `0dcbf52` 中被删除。恢复这个既有映射是最小修复。

## 遇到的问题

- `https://www.patfang.xyz/` 返回 GitHub Pages 404。
- 本次从外网直接请求 `https://PatTianFang.github.io/` 返回 HTTP 200，与用户报告的 404 不一致，可能是其访问时的暂时状态或缓存差异。
- GitHub API 配置查询没有在本次请求中返回内容，无法独立读取 Pages 管理设置。

## 解决方法

恢复根目录 `CNAME` 并写入历史配置值 `www.patfang.xyz`。该值与现有 `www` DNS 记录一致。没有改动 DNS、构建流程或其他网站文件，因为这些修改没有证据支持。

## 验证结果

修改后检查 `CNAME` 内容、Git diff 和工作区状态。GitHub Pages 在新提交发布前仍会依据线上旧配置响应；提交并等待 Pages 部署完成后，需要再次请求 `https://www.patfang.xyz/` 确认线上恢复。

修改前的基线：`https://PatTianFang.github.io/` 返回 HTTP 200；`https://www.patfang.xyz/` 返回 HTTP 404。

## 代码变更摘要

- `CNAME`：恢复 GitHub Pages 自定义域名声明，使其与 `www.patfang.xyz` DNS 目标匹配。
- `Problems/Problem20261015-074824.md`：记录问题证据、判断依据、修复和验证限制。
