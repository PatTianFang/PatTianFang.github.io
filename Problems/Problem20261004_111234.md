# 本次网站仓库清空记录

## 任务目标
将 `https://github.com/PatTianFang/PatTianFang.github.io` 克隆到本地目录 `F:\Programme\pattianfang.github.io`，删除原网站工作树中的全部内容，为后续重新构建网站准备干净目录。

本次保留 Git 元数据 `.git`，以便后续继续使用远端仓库；按项目要求保留本记录文件。

## 思考过程
- 初始目标目录为空，因此先在目标目录执行克隆，不覆盖已有用户文件。
- “删除全部内容”解释为删除工作树中的网站文件，不删除 `.git`，否则后续无法直接提交和推送重建结果。
- 原始对象传输出现长时间无进度，因此改用最新提交的浅层、按需对象获取方式，减少无关历史和文件内容传输。
- 由于当前任务只是清空并准备重建，不需要恢复旧网站文件到工作树。

## 遇到的问题
- 首次克隆在对象传输阶段中断，留下了不完整的 `.git`，当时没有有效 `HEAD`。
- 直接检出最新提交时，按需获取旧文件内容出现卡住，并留下了 Git 的临时锁文件 `.git/index.lock`。
- 当前环境没有可调用的 `apply_patch` 命令，因此本记录使用 PowerShell/.NET 文件 API 创建；未因此修改网站源代码。

## 解决方法
- 通过远端引用确认默认分支为 `master`，并使用 `git fetch --depth=1 --filter=blob:none --no-tags origin master` 获取最新提交。
- 将本地 `master` 指向已获取的提交，清理检出过程中遗留的 Git 临时锁文件。
- 保持工作树为空，不展开旧网站文件；后续可直接在本目录创建新的站点文件并使用现有 `origin` 远端。

- `git rev-parse --is-inside-work-tree` 返回 `true`。
- `git rev-parse HEAD` 成功返回最新提交。
- 当前分支为 `master`，远端 `origin` 指向用户提供的 GitHub 仓库。
- 工作树中除 `.git` 和本 `Problems` 记录外没有旧网站文件。
