# 网站首页首屏设计与实现记录

## 任务目标
为 `PatTianFang.github.io` 重新建立一个可维护的个人网站入口页：采用 Windows 8 磁贴的平直分块，结合 Xbox、Apple TV、PS5 的深色舞台和游戏式焦点状态；当前提供 Gallery、Note、Photo 三个入口，并预留后续扩展方式。

## 思考过程
- 用户明确需要“大屏实际预览”，因此首版使用真实站点 `iframe`，而不是只做静态装饰图；同时提供打开原站的明确按钮。
- 用户还要求后续易维护，因此入口信息集中在 `app.js` 的 `sites` 数组中，新增入口不需要复制 HTML 卡片。
- 为减少 AI 味，避免通用 SaaS 卡片、过量圆角、无意义渐变和模板化营销句；视觉重点放在磁贴、焦点、预览舞台和明确的操作反馈。
- 先做静态 HTML/CSS/JS，不引入框架或构建依赖，降低 GitHub Pages 部署和后续维护成本。

## 遇到的问题
- 原仓库工作树已按上一任务清空，当前没有可以复用的页面、样式或构建配置。
- 真实预览依赖目标站点是否允许被 `iframe` 嵌入；如果目标站点设置了 `X-Frame-Options` 或 CSP，首页会显示降级提示而不是强行伪造预览。
- 设计技能安装源中 `frontend-app-builder` 下载响应较慢，未让它阻塞当前实现；其余相关技能已安装。

## 解决方法
- 新建单页入口、独立样式文件和数据驱动交互脚本，保持结构直观。
- 用 CSS 变量管理主题色，用 `data-theme` 和站点配置切换焦点色。
- 用键盘方向键、数字键和 Enter/Open 操作支持类似主机界面的浏览方式。
- 编写 README，记录入口配置、运行方式、预览限制、视觉约束和后续维护流程。

## 验证结果
- 设计与代码完成后检查 HTML、CSS、JavaScript 文件是否存在且可被静态服务器提供。
- 使用浏览器自动化或等价的本地静态检查验证入口切换、键盘操作和预览链接。
- 若环境不具备浏览器或远程站点禁止嵌入，将明确记录未验证部分，不把静态文件存在误报为完整视觉通过。
